## Требования

| Данные | Свойства |
|---|---|
| Таймкоды слов | меняются только при смене файла или модели STT |
| Спикеры | ошибки, правятся людьми |
| Абзацы | ошибки, правятся людьми |
| Клипы | время + описание, наложения, правки; автоматические и ручные |
| Связи клипов | с другими уроками, клипами, источниками |
| Языки | у урока есть переводы — синхронный перевод, записан вживую, файлы синхронны с оригиналом и видео (одно видео, разные дорожки); иногда в переводе слышен оригинал фоном; оригинал не только на иврите (бывает русский) |
| Доп. данные | на участок времени: рисунок (например, из видео), слайд, ссылка, заметка и т. п.; список типов открыт |

- Правят в **kmedia**: archive-stt даёт API записи.
- Структура (главы, абзацы, спикеры, аннотации) **одна, на шкале оригинала**, на переводы переносится.

## Решения

- **Уроки и файлы — из MDB** (uid, язык, оригинал/перевод, sha1, длительность). Своих таблиц `cu`
  и `media_file` нет. Храним только, из какого `file_uid` построены данные.
- **Слова — неизменяемый слой**, JSON-файлы: `words/<file_uid>/<run_id>.json` (по сути нынешний `stt/`).
  `run_id` нужен, потому что тот же файл можно перераспознать другой моделью.
  `sha` в ключе не нужен: в MDB заменённый файл всегда получает новый `file_uid` (проверено).
- **Источник слов — VTT, если есть.** VTT-субтитры MDB, созданные **до 2027** (дата создания файла в MDB), —
  выверенный датасет, на нём дообучают модель. Есть такой VTT на языке урока → слова и их время берём из него,
  **whisper (ai-trns `/jobs`) не вызываем**; время каждого слова — **выравнивание по аудио**: VTT → SRT →
  ai-trns `/diarize/words` (он и сейчас так делает с SRT от `/jobs`: CTC forced alignment каждого слова внутри
  реплики, VAD — если не вышло; языки `he`/`en`/`ru`). Нет VTT → STT
  ai-trns, как сейчас (стандартный путь). Более поздние VTT не используем.
  Спикеры и абзацы — из того же `/diarize/words`, в обоих случаях.
- **Всё остальное привязано ко времени**: `file_uid + секунды`, не к индексам слов. Тогда смена модели STT
  ничего не ломает: границы при показе прилипают к ближайшему промежутку между словами.
- **База — SQLite** (файл в `DATA_DIR`): одновременные правки, история, запросы поперёк уроков,
  транзакции. В MDB не пишем. Postgres — только если данные захотят читать другие сервисы напрямую.
- **Спикеры — коды ролей** (`rav`, `reader`, `student`), не `הרב / קריין / תלמיד`; подписи рисует клиент.
- **Язык оригинала — из MDB** (файл с `_o_`), вместо жёсткого `he`.

## Схема (SQLite)

```
segmentation  cu_uid, rev, file_uid, words_run_id,
              source (auto|human|migrated), based_on, author, created,
              data json: paragraphs [{start, end, speaker}],
                         chapters   [{type, title, start, end}]
              первичный ключ (cu_uid, rev)

annotation    id, cu_uid, kind (clip|drawing|slide|link|note|…),
              file_uid, start_s, end_s (end_s = start_s — момент),
              source (auto|human), status (suggested|accepted|rejected|deleted|lost),
              needs_review, rev, author, updated,
              data json                                            поля конкретного типа
annotation_rev    annotation_id, rev, data json, author, created   история правок
annotation_text   annotation_id, lang, title, description          тексты по языкам
annotation_link   annotation_id, target_type (cu|annotation|source|topic), target_id, kind
annotation_asset  annotation_id, file_uid (zip MDB), name (имя картинки в zip-е), role
              сами файлы — не у нас: см. «Файлы аннотаций» ниже

time_map      file_uid (перевод или видео), original_file_uid, offset_s (обычно 0),
              lag json [[t_orig, lag_s], …] (отставание переводчика, необязательно), checked_at, status

run           id, cu_uid, kind (first|file|model), file_uid, stage, status (pending|ready|failed),
              words_source (vtt|stt), vtt_file_uid (если из VTT),
              error, jobs json (задачи ai-trns), author, created, updated      вместо state/<uid>.json
migration     id, cu_uid, run_id, from_file_uid, to_file_uid,
              status (pending|done|failed), author, created                   отчёт о переносе
migration_item  migration_id, object (paragraph|chapter|annotation), object_id,
              result (moved|trimmed|lost), old_start, old_end, new_start, new_end,
              resolved_by, resolved_at
```

- **Клип — это аннотация `kind=clip`.** Рисунки, слайды, ссылки, заметки — тоже аннотации. У всех одинаково
  работают правки, история, тексты по языкам, связи, перенос при смене файла и показ на переводах.
  Новый тип — новое значение `kind` и свои поля в `data`, схема не меняется.
- **Данные из видео**: видео — другой `file_uid`, его шкала может отличаться от аудио оригинала;
  обычно та же шкала, что у оригинала (одно видео); `time_map` — на случай расхождения.

- **Текущая ревизия** не хранится, а вычисляется: последняя `human`/`migrated`, если есть, иначе последняя `auto`.
- **Правка**: `PUT` с `If-Match: <rev>`; если ревизия устарела — `409`. Успех — новая ревизия.
- **Автопрогон** пишет ревизию `auto`, ручные не затирает.
- **Автоаннотации** (клипы, кадры из видео): перегенерация заменяет только `source=auto, status=suggested` без ручных ревизий.
- **Аннотация на переводе**: время через `time_map`, текст из `annotation_text` на этом языке, иначе — язык оригинала.
- **Абзацы транскрипта** (`<p>` из `doc2html`) не хранятся, вычисляются выравниванием (`textdiff`).

## Файлы аннотаций (рисунки)

Сами файлы рисунков хранятся и отдаются **в `archive-unzip`**, archive-stt их не хранит.
- Рисунки урока — файл MDB (zip с картинками, `sketches`). `archive-unzip` скачивает его через linker,
  распаковывает в `BASE_DIR/unzip/<file_uid>/` (кэш на диске) и отдаёт:
  - `GET /unzip/<file_uid>` — `index.json`: `[{path, size}]`, все картинки;
  - `GET /unzip_uids?uid=…&uid=…` — `[{uid, full, uniq}]`; `uniq` — без картинок-продолжений
    (эвристика по пикселям, `mark_main_img`);
  - `path` — публичный URL картинки (`public_path`: префикс зависит от развёртывания), отдаётся статикой.
- Аннотация `kind=drawing` (`annotation_asset`) ссылается на `file_uid` zip-а + **имя файла внутри zip-а**
  (не полный `path`: префикс меняется между окружениями; URL собирается из ответа `archive-unzip`)
  и добавляет то, чего нет нигде: **участок времени урока**, к которому относится рисунок, и описание.
- Новые картинки (не из MDB) — открытый вопрос: загружать в MDB (и тогда они приходят через `archive-unzip`)
  или куда-то ещё.

## Смена модели STT (файл тот же)

Время то же. Новые слова ложатся рядом (`words/<file_uid>/<new_run>.json`), ревизии не трогаются.

## Смена файла оригинала (например, вырезали часть)

1. Замечаем: оригинал урока в MDB ≠ `file_uid` текущей ревизии (при запуске или периодической проверкой).
2. Распознаём новый файл.
3. Выравниваем старые слова с новыми по тексту (`textdiff`) → карта «старое время → новое».
4. Переносим по карте границы абзацев, спикеров, главы, аннотации.
5. Целиком в вырезанном → `lost` (аннотация не удаляется, `status=lost`, можно вернуть вручную);
   частично → обрезается, `needs_review`. Каждый перенесённый объект — строка `migration_item`.
6. Пишем ревизию `migrated` с `based_on` и новые `annotation_rev`; старые ревизии на старом файле остаются.
7. Проверяем синхронность переводов с новым оригиналом (`time_map`); переводы, скорее всего, заменены вместе с ним.
8. Редактор в kmedia проверяет отчёт (`GET /cus/{uid}/migrations/{id}`) и отмечает пункты (`resolved_by`). При сильном перемонтаже пометок будет много — это ожидаемо.

## Переводы

Переводы синхронны с оригиналом: та же шкала, на них идёт то же видео. Поэтому **время не пересчитывается** —
секунда в оригинале = та же секунда в переводе. Разница только смысловая: переводчик отстаёт на 2–5 с.

1. **Проверка синхронности** (дёшево, без распознавания): длительности совпадают (±1 с); где в переводе слышен
   оригинал фоном — сравнение дорожек подтверждает сдвиг ≈ 0. Иначе — `offset_s` по совпадению речи и пауз,
   `status=mismatch`, пометка для проверки. Скорее всего, это исключение.
2. **Отставание переводчика** (точнее, необязательно): ai-trns сопоставляет предложения оригинала и перевода
   (многоязычные векторы, по порядку) → `lag` по уроку. Нужны слова перевода (распознавание файла перевода).
3. **Применение на переводе**:
   - шкала та же: время главы / абзаца / аннотации = время оригинала (+ `offset_s`, если есть);
   - если есть `lag`: начало и конец сдвигаются на отставание и прилипают к паузе переводчика — клип на русском
     не обрывается на полуслове;
   - спикеры — роли оригинала («говорит Рав»), хоть голос и переводчика;
   - тексты (заголовки глав, описания аннотаций) — на языке перевода, иначе на языке оригинала.

## Поиск: время ↔ текст

Публичные `GET`, как `/cus/{uid}/markup`. `lang` — язык файла (по умолчанию оригинал); время — секунды этого файла.

| | | |
|---|---|---|
| `GET` | `/cus/{uid}/text?at=754.3&lang=` | слово и абзац в этот момент (спикер, глава) |
| `GET` | `/cus/{uid}/text?from=750&to=800&lang=` | текст участка: слова с временем, абзацы |
| `GET` | `/cus/{uid}/find?q=…&lang=` | где в уроке звучит фраза: `[{start, end, paragraph, context, score}]` |

- **Время → текст**: слова файла отсортированы по времени, двоичный поиск. Слова в памяти (кэш LRU по `file_uid`).
- **Текст → время в уроке**: нечёткое совпадение фразы со словами (`textdiff`), потому что в STT ошибки,
  а запрос часто — цитата из транскрипта. Нормализация: огласовки, конечные буквы, пунктуация, `ё`.
- `/cus/{uid}/find` — только внутри урока; поиск по архиву — Elastic kmedia, время фрагментов — `POST /find` (см. ниже).
- **Какой текст ищем**: слова STT и, если есть, транскрипт kmedia, выровненный по словам (время — от слов).
- **Переводы**: поиск по словам файла перевода; время на оригинале — через `time_map` (`&on=original`).

## Поиск kmedia (Elastic) → время

Документ урока в Elastic (`archive-backend`, `es/content_units_index.go`) **не меняется**: весь транскрипт одним
полем `content`, поиск подсвечивает фрагменты. **Время фрагмента находит kmedia** через archive-stt.

- **При сборке разметки** (раз на урок) сохраняем выравнивание транскрипта со словами (VTT или STT) (`textdiff` уже его
  делает): нормализованный текст транскрипта + для каждого слова позиция в тексте и время. Час урока ≈ 8–10 тыс.
  слов, ≈ 200 КБ.
- **Уже есть похожее**: `archive-unzip` `GET /time_code?uid=&language=` — время для каждого слова транскрипта,
  приблизительно, по субтитрам VTT (`app/timecode/views.py`); его использует kmedia-mdb — «играть с выделенного
  текста» (`PlayByTextBtn`, `fetchTimeCode` в `sagas/assets.js`). Нормализация текста (`clear_str`) синхронна
  с клиентом (`helpers/scrollToSearch/helper.js`). У нас время каждого слова (из VTT или STT) и есть там,
  где нет субтитров → **`/time_code` заменяется целиком**: в `archive-unzip` его убираем, kmedia-mdb
  (`fetchTimeCode`, `PlayByTextBtn`) переходит на `GET /cus/{uid}/timecode` archive-stt. Формат ответа — свой,
  под нашу карту слово → время, совместимость с `/time_code` не нужна. `POST /find` — та же карта.
  Отдельного подсчёта по VTT нет: VTT — источник слов при сборке разметки (см. «Решения»), `/timecode` всегда
  отдаёт время из разметки.
- **`POST /find`** `[{uid, text}]` → `[{uid, start, end, p, chapter, found}]` — пакетно, на всю страницу поиска
  (`p` — индекс `<p>` транскрипта, `chapter` — тип, заголовок, начало и конец главы — для «читать подробнее»
  и проигрывания).
  Фрагмент нормализуется (без `<em>`, пунктуации, лишних пробелов) → точный поиск подстроки (< 1 мс на урок)
  → позиция → время. Не нашли точно (Elastic и мы по-разному извлекли текст из docx) → нечёткий поиск (мс).
- **Нагрузка**: страница поиска ≈ 10–20 уроков × 3–5 фрагментов → один запрос, ≈ 10–50 мс (в основном чтение
  файлов); кэш уроков в памяти (1000 уроков ≈ 200 МБ). GPU / ai-trns не нужны.
- Время показываем **сразу в выдаче** (один запрос на страницу), не по клику.
- Без транскрипта текста урока в Elastic нет — искать нечего. Фрагменты на языке перевода — этап 5.

## Доступ и одобрение правок

- **Вход — Keycloak.** kmedia передаёт токен пользователя (`Authorization: Bearer`), archive-stt проверяет его
  по JWKS realm и берёт `sub` как автора. Скрипты на сервере — как сейчас (локально или `X-API-Key`).
- **Роли (Keycloak)**:

  | Роль | Может |
  |---|---|
  | любой вошедший | предлагать правки (сегментация, аннотации) — они ждут одобрения |
  | `archive-stt-editor` | править без одобрения; одобрять и отклонять чужие предложения |
  | `archive-stt-admin` | всё выше + замена файла, обновление модели, список редакторов |

- **Предложение** — ревизия со `review = proposed`. Текущей она не становится, пока редактор не одобрит.
  Правка редактора сразу `approved`. Текущая ревизия = последняя `approved` (ручная/перенесённая, иначе `auto`).
- **Конфликт**: предложение сделано от ревизии 4, а текущая уже 5 → при одобрении `409`, редактор видит
  обе версии и решает (принять поверх, поправить или отклонить).
- В `segmentation` и `annotation_rev` добавляются `review (proposed|approved|rejected)`, `reviewed_by`, `reviewed_at`, `comment`.

## Эндпоинты записи

Все, кроме помеченных «скрипт», — с токеном Keycloak. Правки — с `If-Match: <rev>`; устарела — `409`.

**Файл и модель** (`archive-stt-admin` или скрипт на сервере), ответ `202` + запуск, ход — `GET /cus/{uid}/runs/latest`:

| | | |
|---|---|---|
| `POST` | `/cus/{uid}/file` `{file_uid?}` | замена файла оригинала: без `file_uid` — взять текущий оригинал из MDB. Распознать → перенести ручные ревизии и аннотации → ревизия `migrated` + отчёт `migration` (в БД) |
| `GET` | `/cus/{uid}/migrations[/{id}]` | отчёты о переносе: что перенесено, обрезано, потеряно; что уже проверено |
| `POST` | `/migrations/{id}/items/{item_id}/resolve` | отметить пункт проверенным (`archive-stt-editor`) |
| `POST` | `/cus/{uid}/model` `{model?}` | обновить результат модели на том же файле: новые слова и ревизия `auto`; ручные ревизии остаются текущими |
| `POST` | `/cus/{uid}/markup` | первый запуск (сейчас `POST /markup?uid=`); и для скриптов |
| `GET` | `/cus/{uid}/runs[/latest\|/{id}]` | запуски: тип, стадия, статус, ошибка (сейчас `/markup/{uid}/status`) |

**Сегментация** (абзацы, спикеры, главы):

| | | |
|---|---|---|
| `GET` | `/cus/{uid}/segmentation?rev=` | текущая или указанная ревизия |
| `GET` | `/cus/{uid}/segmentation/revisions` | история: кто, когда, источник, статус одобрения |
| `PUT` | `/cus/{uid}/segmentation` | новая ревизия целиком; редактор — сразу текущая, остальные — предложение |

**Аннотации**:

| | | |
|---|---|---|
| `GET` | `/cus/{uid}/annotations?kind=&status=&lang=&from=&to=` | список (публично — только одобренные) |
| `POST` | `/cus/{uid}/annotations` | создать: `kind`, время, `data`, тексты, связи, файлы |
| `GET` | `/annotations/{id}` | одна аннотация с текстами и связями |
| `PATCH` | `/annotations/{id}` | правка (время, `data`, статус кандидата `accepted/rejected`) |
| `DELETE` | `/annotations/{id}` | удаление (мягкое, `status=deleted`) |
| `GET` | `/annotations/{id}/revisions` | история |
| `PUT` | `/annotations/{id}/texts/{lang}` | название и описание на языке |
| `POST` / `DELETE` | `/annotations/{id}/links[/{link_id}]` | связи с уроками, аннотациями, источниками |

Правки аннотаций от не-редакторов — тоже предложения.

**Одобрение** (`archive-stt-editor`):

| | | |
|---|---|---|
| `GET` | `/proposals?uid=&kind=&status=proposed` | очередь предложений |
| `POST` | `/proposals/{id}/approve` | принять (`409` при конфликте) |
| `POST` | `/proposals/{id}/reject` `{comment}` | отклонить |

**Админка** (`archive-stt-admin`):

| | | |
|---|---|---|
| `GET` | `/admin/editors` | кто имеет роль `archive-stt-editor` (из Keycloak) |
| `PUT` | `/admin/editors/{user_id}` | дать роль |
| `DELETE` | `/admin/editors/{user_id}` | снять роль |

Источник правды — роль в Keycloak; archive-stt её только читает и меняет через Keycloak Admin API
(сервисный аккаунт с правом назначать только эту роль).

## Этапы

Сначала archive-stt (и kmedia-admin, ai-trns), kmedia-mdb — последним этапом (решение 2026-11-23). Правка людьми
и переводы — не критичны, они в конце.

### Этап 1 — основа и чтение разметки (оригинал)

archive-stt:
- [x] Спикеры кодами ролей (`rav`, `reader`, `student`); язык оригинала из MDB вместо `he`.
- [x] SQLite и таблицы `run`, `segmentation` (только `auto`); `state/<uid>.json` → `run`;
      импорт `stt/<uid>/<run>.json` → `words/` + `segmentation` rev 1 `auto` (абзацы во времени).
- [ ] Слова из VTT: ищем в MDB субтитры урока на языке оригинала, созданные до 2027 (запрос — как `vtt_q`
      в `archive-unzip` `app/timecode`); есть → VTT → SRT → сразу `/diarize/words` (шаг `/jobs` пропускаем),
      дальше сборка как обычно; `words_source=vtt`. Уроки, уже собранные по STT, у которых есть такой VTT, —
      пересобрать. Новых эндпоинтов в ai-trns не нужно.
- [x] Пути под `/cus/{uid}/…`: `GET /cus/{uid}/markup` из текущей ревизии (коды спикеров, `original_lang`),
      `POST /cus/{uid}/markup`, `GET /cus/{uid}/runs[/latest|/{id}]`. Старые `/markup…` убрать — на проде ещё
      ничего нет, совместимость не нужна.

### Этап 2 — поиск: время фрагментов и время ↔ текст (первоочередное)

archive-stt:
- [ ] При сборке сохранять выравнивание транскрипта со словами (текст + позиция и время слова); слова
      транскрипта — той же нормализацией, что `clear_str` в `archive-unzip` / kmedia-mdb.
- [ ] `GET /cus/{uid}/timecode?lang=` — время каждого слова транскрипта из разметки; заменяет
      `archive-unzip /time_code`. Нет разметки → `404`.
- [ ] `POST /find` `[{uid, text}]` → время фрагментов из подсветки Elastic; кэш уроков в памяти.
- [ ] Время → текст: `/cus/{uid}/text` (`at`, `from/to`), кэш слов в памяти.
- [ ] Текст → время в уроке: `/cus/{uid}/find`, нечёткое совпадение по словам.

### Этап 3 — автоматические аннотации и операции

archive-stt:
- [ ] Таблицы `annotation`, `annotation_rev`, `annotation_text`; `GET /cus/{uid}/annotations`, `GET /annotations/{id}`.
- [ ] Автокандидаты клипов (например, из глав `qa` и `reading`), `status=suggested`.
- [ ] Keycloak: проверка токена (JWKS), роль `archive-stt-admin`.
- [ ] Принять / отклонить кандидата (`PATCH /annotations/{id}`, только `admin`); публично — только принятые.
- [ ] `POST /cus/{uid}/model` — обновить результат модели на том же файле.
- [ ] `POST /cus/{uid}/file` — замена файла, пока **без переноса** (ручных правок ещё нет): новый файл → новая
      ревизия `auto`, автокандидаты заново.

kmedia-admin:
- [ ] Доступ по роли `archive-stt-admin`, токен `kc` в запросах.
- [ ] **Запуски**: по `uid` — состояние (`/cus/{uid}/runs/latest`), «заменить файл» и «обновить модель»
      с подтверждением; ход запуска.
- [ ] **Автокандидаты аннотаций**: список `suggested` по урокам, принять / отклонить пачкой.

### Этап 4 — правка людьми

archive-stt:
- [ ] Роль `archive-stt-editor`; любой вошедший — предложения.
- [ ] API записи: `PUT /cus/{uid}/segmentation`, `POST/PATCH/DELETE` аннотаций, тексты, связи (`annotation_link`),
      всё с `If-Match` / `409`.
- [ ] Предложения и одобрение: `review` в ревизиях, `/proposals`, approve / reject, конфликт `409`.
- [ ] Рисунки: аннотации `drawing` со ссылкой на картинку `archive-unzip` (`file_uid` zip-а + `path`).
- [ ] Перенос при смене файла оригинала (теперь есть что переносить); отчёт `migration` / `migration_item`,
      `/cus/{uid}/migrations`, `resolve`.
- [ ] Админка: `/admin/editors` через Keycloak Admin API.

kmedia-admin:
- [ ] Доступ и для `archive-stt-editor`.
- [ ] **Очередь предложений**: `GET /proposals` с фильтрами (урок, тип, статус), постранично.
- [ ] **Просмотр предложения**: было / стало (абзацы, спикеры, главы, аннотация); принять, отклонить с комментарием;
      при `409` — показать текущую версию рядом и дать выбрать.
- [ ] **Отчёты о переносе**: список `migrations`, пункты `moved / trimmed / lost`, старое и новое время,
      отметка «проверено»; ссылка на урок в kmedia на нужное время.
- [ ] **Редакторы** (`admin`): список, выдать / снять роль.

### Этап 5 — переводы

archive-stt:
- [ ] Разметка по `lang`: время оригинала (+ `offset_s`), тексты на языке перевода, иначе оригинала.
- [ ] Проверка синхронности (`time_map`: `offset_s`, `status`), пометка расхождений.
- [ ] Точнее (необязательно): распознавание перевода + `lag` от ai-trns; сдвиг границ на отставание переводчика.
- [ ] `/text` и `/find` по файлу перевода.
- [ ] Время фрагментов поиска на языке перевода: выравнивание транскрипта перевода со словами перевода.

ai-trns:
- [ ] Сопоставление оригинала и перевода: вход — слова оригинала и перевода (или их задачи), выход —
      пары предложений с временем и уверенностью → `lag`. Многоязычная модель предложений (LaBSE / multilingual-e5),
      сопоставление по порядку (DTW). Асинхронная задача, как `/jobs`.
- [ ] (необязательно) Проверка синхронности дорожек по звуку, где в переводе слышен оригинал.

### Этап 6 — kmedia-mdb (в конце)

Всё, что видно на kmedia, — после того как archive-stt готов: API этапов 1–5 к этому времени стабилен.

kmedia-mdb — к этапу «основа и чтение разметки (оригинал)»:
- [ ] `fetchMarkup` → `GET /cus/{uid}/markup` (новый формат); коды спикеров → подписи через i18n (`public/locales/*`).

kmedia-mdb — к этапу «поиск: время фрагментов и время ↔ текст (первоочередное)»:
- [ ] «Играть с выделенного текста» (`fetchTimeCode` в `sagas/assets.js`, `PlayByTextBtn`) → `GET /cus/{uid}/timecode`
      archive-stt вместо `archive-unzip /time_code`.
- [ ] Результаты поиска: фрагменты подсветки → `POST /find` одним запросом → время у каждого фрагмента сразу
      в выдаче, переход в урок на это время.
- [ ] **Проиграть на странице поиска**: у фрагмента кнопка ▶ — встроенный плеер (аудио; видео — по желанию)
      с времени фрагмента, без ухода со страницы; играет до конца абзаца / главы или пока не остановят;
      одновременно играет один фрагмент.
- [ ] **Читать подробнее на странице поиска**: раскрыть фрагмент — абзац транскрипта целиком и соседние
      (по `p`, транскрипт kmedia `doc2html`), заголовок и тип главы; найденное подсвечено; ссылка
      «открыть урок здесь».
- [ ] Выделение текущего слова / абзаца в транскрипте (`/text?from&to`).
- [ ] Поиск фразы в уроке (`/find`) → перемотка.

kmedia-mdb — к этапу «автоматические аннотации и операции»:
- [ ] Аннотации в плеере: клипы на шкале и в списке.

kmedia-mdb — к этапу «правка людьми» (после входа; без роли `editor` — уходит на одобрение, это видно пользователю):
- [ ] **Режим правки урока**: включается кнопкой, только для вошедших.
- [ ] **Абзацы и спикеры**: разделить / склеить абзац, сдвинуть границу (прилипает к промежутку между словами),
      сменить спикера; сохранить как одну ревизию.
- [ ] **Главы**: тип, заголовок, границы.
- [ ] **Аннотации**: создать из текущего места / выделения (начало, конец по плееру), тип, название, описание
      на языке, связи, выбор рисунка урока (из `archive-unzip /unzip/<file_uid>`); правка и удаление.
- [ ] Рисунки, слайды, ссылки в плеере; рисунок — на своём участке.
- [ ] Связи клипа: «см. также» — переход в другой урок на время клипа.
- [ ] **Конфликт `409`**: сообщить, что урок изменили, показать новую версию, не терять свою правку.
- [ ] **Мои предложения**: статус (ждёт / принято / отклонено с комментарием).
- [ ] **Пометки после переноса** (`needs_review`) видны редактору прямо в уроке.
- [ ] e2e (Playwright): чтение аннотаций, правка абзаца, отправка на одобрение.

kmedia-mdb — к этапу «переводы»:
- [ ] Разметка и аннотации на переводе: заголовки и описания на языке интерфейса / дорожки.
